# PEF-DS09 · API Exchange Contracts

## INTRODUCTION

This standard is the **canonical owner of HTTP REST contracts** for external clients (Android JSON; residual Desktop XML) and shared conventions (`/api/v1/`, JWT, correlation ID, error format).

It does not redefine database tables: reference PEF-DS01…DS08 for field semantics. On loopback, the portal/station talks directly to the Web Backend; on lab LAN, the portal enters through portal-lan HTTPS :5443 and Android enters through Gateway :8080 (runtime discovery). Frame-by-frame vision is defined in PEF-DS10 (WSS).

---

## 1. Standard Explanation

### 1.1 Definitions

| Term | Meaning |
| :--- | :--- |
| **Microservice** | Independent REST API running in its own container. |
| **Contract** | Method + path + headers + request/response body + HTTP status codes. |
| **JSON/XML equivalence** | Identical semantics; different `Content-Type` / `Accept`. |

### 1.2 Usage

Android → HTTPS + JSON via Gateway :8080 (LAN discovery of `pef-gateway` / `/healthz`). Desktop XML is a residual contract. Gateway applies correlation and rate limiting; each MS validates JWT.

---

### 1.3 Conventions

#### 1.3.1 Common Headers and Envelope

| Field / header | Required | Meaning |
| :--- | :--- | :--- |
| `Authorization` | Yes (protected routes) | `Bearer <access_token>` |
| `Content-Type` | Yes when body is present | `application/json` or `application/xml` |
| `Accept` | Recommended | Matches client format |
| `X-Correlation-ID` | Yes (or generated by gateway) | End-to-end traceability |

**Common error (body fields)**

| Field | Type | Meaning |
| :--- | :--- | :--- |
| `error` | string | Stable error code (`invalid_credentials`, `conflict`, …). |
| `message` | string | Human-readable text (localizable in UI). |
| `correlation_id` | string | Echo of the header. |
| `details` | object/array | Optional; no secrets or stack traces. |

```json
{
  "error": "conflict",
  "message": "The session is already closed",
  "correlation_id": "corr-demo-1001",
  "details": {
    "session_id": "cccccccc-cccc-cccc-cccc-cccccccccccc",
    "status_code": "closed"
  }
}
```

HTTP status codes: 400, 401, 403, 404, 409, 422, 429, 500/503.

#### 1.3.2 Auth / Identity Service

Machine/Android base: `/api/v1/auth` (allow-listed in Gateway).

Portal/browser: cookie routes on AuthService; behind portal-lan, `AUTH_BROWSER_URL=/auth` (same-origin relative path) is valid. An absolute auth URL is not required for lab LAN.

| Method | Endpoint | Purpose | Access |
| :--- | :--- | :--- | :--- |
| POST | `/login` | Credentials → tokens | Public authenticatable |
| POST | `/refresh` | Renews access token | Refresh token |
| POST | `/logout` | Revokes in Redis | JWT |
| GET | `/me` | Profile + roles | JWT |
| GET | `/permissions` | Effective permissions | JWT |

**Complete `POST /login` request**

| Field | Type | Nullable | Meaning |
| :--- | :--- | :--- | :--- |
| `email` | string | NO | Login email (DS01). |
| `password` | string | NO | Plaintext over TLS in transit; never logged. |

```json
{
  "email": "ana.perez@demo.local",
  "password": "[REDACTED]"
}
```

**Complete `POST /login` response**

| Field | Type | Meaning |
| :--- | :--- | :--- |
| `access_token` | string | Short-lived JWT. |
| `refresh_token` | string | Renewal token. |
| `token_type` | string | `Bearer`. |
| `expires_in` | int | Access token lifetime in seconds. |
| `user` | object | Profile summary. |
| `user.id` | uuid | |
| `user.name` | string | |
| `user.email` | string | |
| `user.institution_id` | uuid | |
| `user.ui_preferences` | object | See DS01. |
| `user.roles` | array | Role codes. |

```json
{
  "access_token": "[JWT_REDACTED]",
  "refresh_token": "[REFRESH_REDACTED]",
  "token_type": "Bearer",
  "expires_in": 900,
  "user": {
    "id": "22222222-2222-2222-2222-222222222222",
    "name": "Ana Perez",
    "email": "ana.perez@demo.local",
    "institution_id": "11111111-1111-1111-1111-111111111111",
    "ui_preferences": { "locale": "es", "theme": "dark" },
    "roles": ["station_operator"]
  }
}
```

Product v1 roles in `user.roles`: `station_operator`, `spd_supervisor`, `it_admin`, `or_charge`.

### 1.5 Standard Rationale

**Design decisions taken**

1. **Single DS owning endpoints** to avoid redefining HTTP across table DS documents.
2. **Android JSON** as the active external client; residual Desktop XML preserves identical semantics.
3. **Environment-specific entrypoints:** loopback portal → Web Backend directly; lab LAN → portal-lan :5443 (+ same-origin `/auth`); Android → Gateway :8080. Do not assume "portal is always outside the gateway."
4. **409** for session state conflicts.

**Rejected alternatives**

| Alternative | Why not |
| :--- | :--- |
| Single monolithic API for portal and mobile | Couples release cycles and conflicts with course requirements. |
| Single GraphQL endpoint | Outside agreed scope; versioned REST is sufficient. |
| Document endpoints only inside DS04/DS05 | Causes duplication; this DS is the canonical source. |
